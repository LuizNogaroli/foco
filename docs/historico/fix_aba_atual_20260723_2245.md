# Correção do Bug de Sobrescrita de Status da Aba 2 (Aba_Atual = 1)
**Data:** 23/07/2026 22:45

## Contexto
O usuário relatou que ao clicar em "Salvar e Enviar" na Aba 2, o formulário completava o fluxo, redirecionava para o Kanban, mas o status do processo não era atualizado para "Análise de Viabilidade", permanecendo como "Diagnóstico Preliminar". 

Após investigação profunda utilizando breakpoints no JavaScript e inspeção do payload via `dd($request->all())` no `ProcessoController::tramitar`, descobrimos que o navegador estava enviando a chave `"aba_atual" => "1"`, a despeito do DOM em `aba2.blade.php` possuir `<input type="hidden" name="aba_atual" value="2">`. Devido a este envio anômalo, o Laravel executava a condicional referente à Aba 1 (que redefine o status para Diagnóstico Preliminar).

## Estado Anterior (Antes)
No arquivo `app/Http/Controllers/ProcessoController.php` (método `tramitar`), não havia uma validação que cruzasse o payload com a aba:
```php
        $validatedData = $request->except(['_token', 'next_aba', 'aba_atual']);
        $nextAba = $request->input('next_aba', 1);
        $abaAtual = $request->input('aba_atual', null);
        $effectiveAba = $nextAba !== 'index' ? $nextAba : $abaAtual;
```

## Estado Novo (Depois)
Foi introduzido um "safety fallback" no Controller que atua como uma barreira de segurança heurística. Se o request contém um campo exclusivamente presente na Aba 2 (ex: `situacao_ocupacional`), forçamos inequivocamente a `$abaAtual` para `'2'`.
```php
        $validatedData = $request->except(['_token', 'next_aba', 'aba_atual']);
        $nextAba = $request->input('next_aba', 1);
        $abaAtual = $request->input('aba_atual', null);

        // SAFETY FALLBACK: Se o navegador enviou aba_atual=1 por algum motivo misterioso de cache, 
        // mas o payload contém campos exclusivos da Aba 2, forçamos abaAtual para 2.
        if ($request->has('situacao_ocupacional')) {
            $abaAtual = '2';
        }

        $effectiveAba = $nextAba !== 'index' ? $nextAba : $abaAtual;
```

## Plano de Rollback / Desfazer
Para reverter esta mudança:
1. Abra `app/Http/Controllers/ProcessoController.php`.
2. Vá para a função `tramitar`.
3. Remova o bloco condicional `if ($request->has('situacao_ocupacional')) { $abaAtual = '2'; }`.
4. O código retornará a confiar cegamente na propriedade `aba_atual` enviada pelo client (o que pode reintroduzir o bug se o cache/DOM do usuário continuar enviando o valor errado).
